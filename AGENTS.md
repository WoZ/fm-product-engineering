# Repository Instructions

- Write repository content in American English.
- Before changing files, read the conventions relevant to the task using the routes below.
- Store distributable plugins under root `plugins/`.
- Prefix plugin identifiers with `fm-`; omit that prefix from skill identifiers.
- Keep shared skill instructions portable and installed packages independent of repository governance.
- For every change, check affected current instructions and documentation for consistency using [Change management](repository-governance/conventions/change-management.md). Report discrepancies; edit related documents only when their update is part of the user's request.
- Report the verification performed and its limitations with each change.

## Required Reading

Paths below are relative to the repository root. Read all rows relevant to the task; do not load unrelated conventions.

| Task | Convention |
|---|---|
| Create or rename a file, directory, plugin, or skill; write brand references | [Naming](repository-governance/conventions/naming.md) |
| Add repository areas, plugins, or packaged resources | [Repository layout](repository-governance/conventions/repository-layout.md) |
| Create or change skill behavior or supporting resources | [Skill authoring](repository-governance/conventions/skill-authoring.md) |
| Add agent configuration or change distribution behavior | [Agent compatibility](repository-governance/conventions/agent-compatibility.md) |
| Write or restructure documentation | [Documentation](repository-governance/conventions/documentation.md) |

| Change plugin versions or prepare releases | [Versioning and releases](repository-governance/conventions/versioning-and-releases.md) |

Conventions define repository policy. Decision records explain rationale; README files provide navigation. For governance navigation, see [Repository governance](repository-governance/README.md).
